# qson-ui-workflow - AI 做 UI 工作流

## 使用

- Invoke this skill before generating a UI with AI, when a generated page looks template like, or when the user mentions qson_ui_workflow or asks how to brief an AI for design.

- This is the method skill of the qson-ui-skills family. The effect skills hold what to build, and this skill holds how to get an AI to build it well.

- Read [the workflow reference](references/workflow.md) for the full method and [the checklist](references/checklist.md) before and after generation.

- For the Codex executor toolkit, read [the Codex toolkit reference](references/codex-toolkit.md): six capability packs (Computer Use, Caveman, Playwright, Superpowers, office trio, hollandcut), the clarify-before-coding flow, isolated trial installs, and the restart-and-self-report verification.

## 工作流七步（第2/16/18集）

- Prepare the skills first, then clarify what the page must do, then align effect terminology, then set the aesthetics, then motion, then code with restraint, then automated testing and fixing, in that order and without skipping.

- The division of labor never changes: one role clarifies what to do, one role decides how it should look, one role names effects precisely, and the executor only executes.

## 去模板感规则（第1/2/16/18集）

- Anchor one strong aesthetic direction before generating and never let the AI average freely; give it rules it cannot cross rather than vague direction advice.

- Load a brand token set when one exists so the AI has a stance, and treat the known AI defaults, purple gradients, centered layouts and generic fonts, as a reverse checklist to remove.

- Translate vague wishes into named effects with implementation notes before any coding, land every effect in concrete details, and run an aesthetic before and after comparison instead of retrying prompts blindly.

## 术语对齐（第16集）

- When a wish cannot be named, name it first: identify the effect name and its implementation approach, then hand the named effect to the executor together with the design rules.
