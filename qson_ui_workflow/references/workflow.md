# AI 做 UI 工作流（《Skill实战》方法条全文）

来源：西瓜同学《UI高级审美设计｜Skill实战》合集（197.6 万播放，21 集）。方法结论只取自完整观看的第 1、2、16、18 集；其余集数仅用标题与章节要点做主题标注，不作方法来源。第1集单条视频页：https://www.douyin.com/video/7645900668217085236（2026-05-31 发布）。

## 核心判断

AI 做网页的差距在工作流：模型决定下限，Skill 决定上限。把设计经验沉淀成可复用的规则与 Skill，让 AI 在约束内执行，而不是反复换提示词碰运气。工作流是直接以 Skill 约束生成页面代码，已看各集未见"先出设计图再转代码"的独立出图环节（视频未明示）。

## 七步工作流

1. 编码前先装好 Skill（前置准备）。
2. 先想清楚页面要做什么，明确需求。
3. 用术语 Skill 对齐效果：先准确说出效果名称与实现方式，再交给执行工具（Codex、WorkBuddy）。
4. 定审美：UI 设计 Skill 管排版、配色与交互细节。
5. 做动效：GSAP 做滚动触发、时间轴编排、错峰入场。
6. 写代码：ponytail 把关工程思维，尽量减少代码量。
7. 自动测试与修复：Playwright MCP 自动测试、自动修 Bug。
分工恒定（第18集）：想清楚做什么 / 决定怎么设计 / 把说不清的效果准确告诉 AI，三个角色分开；只拼页面不做动效与细节打磨，是"拼页面"与"到位页面"的分界。

## 术语 Skill 是什么（第16集）

- 定义：把模糊设计描述翻译成专业术语的中间层。不出图、不是美化提示词，而是动手之前先统一"叫法"和"做法"：识别效果叫什么、该怎么实现，再把结论交给执行工具与 UI 设计 Skill 落地。
- 用法四步：感觉或参照表达 → 术语 Skill 说出效果名与实现方式 → 交给执行工具 → UI 设计 Skill 完成排版配色交互，并判断技术选择是否合适、提示坑点。
- 解决的问题：用户说不清、AI 听不懂。没有准确名称 AI 只能猜，容易跑偏、质感差。
- 示例：①悬停抬起加邻位让位（避免宽高一起动）；②扇形排列/封面流（注意角度、大小、亮度、背景）；③3D 环形画廊（注意层级与质感，技术选择由 UI 设计 Skill 判断）。
- 该 Skill 的具体产品名视频未明示（第16、18集均未给名），不补填。

## 去模板感 9 条

1. 先锚定一种鲜明审美方向再生成，不让 AI 自由取平均值（第1集 frontend-design 给 6 个方向选其一：Swiss/Brutalist、Neon Cyberpunk、Nordic Minimal、Editorial、Organic Warm、Material Brutal）。
2. 给 AI 不能越过的设计准则而非方向建议；每个场景有对应规则与反模式（第1集）。
3. 用品牌 Token 直接加载让 AI 立刻有立场（第1集 awesome-claude-design 把品牌设计系统打包成一个 DESIGN.md，画面列举 Stripe、Linear、Vercel、Raycast、Notion、Apple 等）。
4. 审美校验做前后对比：同提示词下默认输出与加 Impeccable 后输出做 BEFORE/AFTER，逐条改掉套路化写法，而非只换提示词重试（第1集）。
5. 效果落到实现细节，不停留在感觉词（第16集约束示例见术语一节）。
6. 模糊需求先翻译再动手，不让 AI 猜（第16集）。
7. 按审美、动效、工程、测试顺序推进，不跳步（第2、18集）。
8. AI 默认表现当反向检查项：紫色渐变、居中布局、Inter 字体、千篇一律、没有立场 — 出现即回锚定与约束修正（第1集）。
9. 同一页面保持设计语言一致，由 UI 设计 Skill 统筹排版、配色与交互细节（第16集）。
注：第1集评论区提到的"37 条反模式检测"出自评论区补充、非视频本体，引用须注明来源。
